A bit about me

I'm a full-stack developer. I learned the way I like to work: by building real software and then defending how it works, not by following tutorials.

That shaped how I approach problems. I'm comfortable using libraries, but while I'm still studying I choose to build the hard parts myself, because that's how I understand every layer of a task and how programming works underneath. These were separate school projects: a virtual-DOM frontend framework, an authoritative game server with client-side prediction that I later extended with AI opponents, a full-stack matchmaking platform (Spring Boot and React) with real-time chat that pairs people by scoring them across several data points, and a GraphQL gateway in front of it that turns a dozen mobile requests into one.

I care about the parts that decide whether a product actually holds up: real-time correctness, performance, clean architecture, and tests. Beyond the projects above I've shipped Spring Boot REST APIs, a Laravel app, real-time backends, an Electron desktop tool, and command-line apps, so I'm comfortable moving around the stack. My main stack is JavaScript and TypeScript, Java and Spring Boot, React, and Node.js.

kood (kood/Järva)

Estonia · taught in English · hybrid study
Currently enrolled

kood is an intensive, peer-to-peer program with no teachers and no classes. It is fully project-based: you build real software of increasing difficulty, then defend each project in a peer code review. Reviewers first work through the testing questions, then read through the code, and finally decide on acceptance and give feedback. The course runs about 12 to 15 months, and tuition is deferred, so you pay it back only after you're hired.

Every project on this page is work I built and defended in the program.

A frontend framework, from the ground up

dot.js

Featured

My own declarative UI framework, about 720 lines with no dependencies: a virtual DOM, components, routing, and a state store. I built a full Trello-style Kanban app with it to prove it works.

  • Virtual DOM with diffing, so a 1-in-1000 change makes exactly 1 DOM mutation
  • Document-level event delegation: 500 buttons share 1 real listener
  • State store with named actions and subscribers, plus a hash router with params
  • VirtualList windowing: 10,000 items in state, about 26 rows in the DOM

API gateway

Match-Me GraphQL

A GraphQL gateway that sits in front of the Match-Me REST API. It exists to cut mobile data usage: a screen that used to need a dozen REST calls becomes one request that returns exactly the fields you ask for, with no changes to the backend.

  • DataLoader batches and de-duplicates the internal REST calls per request
  • JWT pass-through keeps auth as a single source of truth in the backend
  • A Socket.IO to GraphQL subscription bridge for real-time events
  • REST and GraphQL run side by side, with no changes to the original server
